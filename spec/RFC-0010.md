# BMO RFC-0010 — Rendering Profile (v0.10.0-alpha, DRAFT)

Status: **DRAFT**, depends on RFC-0002..0006. This document draws the
conformance boundary between *stored bytes* (previous RFCs) and *pixels*.
Two renderers may rasterize differently; they MUST agree on what the
file says, and on the mapping rules below.

## 1. The one honesty rule

A renderer MUST NOT invent layout the file does not contain. No font
metrics are stored in v0.10, therefore **no line breaking, no
hyphenation, no pagination from text measurement**. One paragraph renders
as one text element (one tspan per run, laid out by the text engine with
real font metrics — runs MUST NOT be stacked at one position);
overflow handling (clip/scroll/scale) is declared in
output metadata, never silently wrapped. Fake wrapping caused decades of
"same file, different page count" bugs — BMO renderers do not do it.

## 2. Text mapping (reference: SVG)

* Runs in logical order inside one `<text>` flow; paragraph `dir`
  `rtl` → `direction="rtl" unicode-bidi="embed"` (same for `Arab`-script
  runs); `lang` → `xml:lang`. Shaping and bidi resolution belong to the
  text engine (UAX #9), not the file walk.
* `align`: `center` → `text-anchor="middle"`, `right`/`end` → `"end"`,
  `justify` renders as `start` (no metrics to distribute space — declared,
  not faked). `left`/`start` → default.
* Lists: marker prefix (`•` for bullet, counters for decimal) computed
  per list id in document order; `level` indents.
* Styles: `b` → bold, `i` → italic, `size` (pt) → px at 96dpi,
  `color` (hex) → fill. Missing keys inherit nothing (no cascade in
  v0.10 — `basedOn` is informational for renderers, normative for editors).
* `text` legacy kind renders like a single-line note.

## 3. Tables, graphics, sheets, slides

* Tables: grid from row/cell structure (equal column split in v0.10;
  `gridSpan` honored), one line per paragraph per cell.
* Shapes: `rect`/`ellipse`/`line`/`path` map 1:1 to SVG primitives,
  bmu→px at 96dpi; `fill`/`line` map to fill/stroke; `"none"` stays
  unpainted. Unknown `shape` discriminators MUST fail the render of that
  object (placeholder + warning), never misdraw (RFC-0004 §6).
* Images: v0.10 renders a labeled placeholder (mime, byte size, sha
  prefix). Embedding original bytes as data-URIs is allowed ONLY when
  the mime is directly renderable by the output format AND the bytes are
  passed through untouched; test goldens use synthetic bytes, so the
  reference renderer always shows placeholders there.
* Sheets: HTML tables in address order; formulas show cached values with
  `data-f` carrying the source; merges → colspan/rowspan; errors as text.
  No calculation in the renderer (RFC-0005 §1).
* Slides: one SVG page each (fixed 960×540 viewport in v0.10);
  transitions and notes are declared data, not playback.

## 4. Fonts

System fonts only in v0.10 (no embedding/subsetting yet — that needs the
licensing story from the BMO vision first). `lang`/`script` metadata
MUST be emitted so the text engine can pick fonts; renderers MUST NOT
drop them.

## 5. Conformance

* Byte-determinism: same file + same renderer version = identical bytes.
* Well-formedness: SVG outputs parse as XML; HTML outputs contain the
  stored values verbatim (spot-checked, not eyeballed).
* Logical-order preservation: the character sequence in the output MUST
  equal the stored run sequence (bidi controls go to the text engine via
  attributes, never by reordering bytes).
* Vectors: `text`/`table`/`graphics`/`deck`/`sheet`/`hello` goldens all
  render (see `tests/test_render.py`); `legacy_hello` is the permanent
  backward-compat render check.
