# BMO RFC-0005 — Spreadsheet Model (v0.5.0-alpha, DRAFT)

Status: **DRAFT**, depends on RFC-0001 + RFC-0002. Defines workbooks,
sheets and cells as portable data. Formula *evaluation* is a domain
engine above the format; this document guarantees the stored grid,
references and dependencies are unambiguous without parsing formula text.

## 1. Anti-goals (explicit)

The container does NOT compute. No calc engine, no function registry, no
number-format rendering here. What it MUST preserve exactly: addresses,
values, formula strings, dependency lists, merges, names.

## 2. Kinds and bodies

### 2.1 `workbook` — `{calc?: {mode: "auto"|"manual"}, names?: map?}`

Root alternative (`parent = 0`). Children, if present, MUST be `sheet` or
`image` objects (plus resource kinds `style`/`numfmt`/`list-def`).

### 2.2 `sheet`

```text
{
  name: tstr 1..31 chars (REQUIRED, unique within workbook),
  cells: { addr: cell } (REQUIRED, may be empty),
  merges?: [ [r1,c1,r2,c2], … ]   # 0-based uints, r2≥r1, c2≥c1
}
```

* Parent kind MUST be `workbook`. Sheets hold NO child objects (cells
  are inline) — any child → `STRUCTURE_INVALID`.
* Addresses: `^$?[A-Za-z]{1,3}$?[0-9]{1,7}$`, column 1..16384, row
  1..1048576 (Excel-compatible bounds adopted as limits; anything larger
  or malformed → `STRUCTURE_INVALID`). `$` markers are preserved verbatim
  (absolute/relative intent) but do not change validation.

### 2.3 Spreadsheet drawing images

An XLSX picture is an `image` object (RFC-0004) under the workbook, alongside
its worksheet. Its body MUST include `sheet` (the exact unique worksheet
name) and `anchor` (an opaque map preserving the source anchor kind and
coordinates). Both fields are required together; the named worksheet MUST
exist in that workbook. Readers that do not interpret anchors MUST preserve
them unchanged.

### 2.4 Cells (inline maps, not objects)

```text
{
  v: number|tstr|bool|null  OR  err: tstr,   # exactly one REQUIRED
  f?: tstr (non-empty formula source),
  deps?: [addr…] (REQUIRED whenever f is present),
  s?: { $ref }   # numfmt/style reference
}
```

* `v`+`err` together, or neither, is invalid. NaN is not canonical and
  is rejected. Dates are numbers + `numfmt` (no date type at this layer —
  deliberate, kills an entire class of interop bugs).
* **`deps` is the contract.** A writer MUST list every cell the formula
  reads; readers build calc chains and dirty regions from `deps` WITHOUT
  parsing `f`. Formula text is opaque and preserved byte-exact.
  `f` without `deps` → `STRUCTURE_INVALID`.
* `err` values SHOULD look like `#DIV/0!` but any text is accepted
  (external engines define their own vocabulary).

### 2.5 `numfmt` — `{code: tstr (REQUIRED)}`

Format codes are opaque text (`"#,##0.00"`, …). Rendering them is the
spreadsheet engine's job.

## 3. Chunk mapping, features

* `GENERIC_OBJECT` in v0.x (`0x0040–0x004F` reserved).
* `DOCUMENT.docType = "spreadsheet"`, features include `"sheet.v1"`.

## 4. Test vector: `sheet.bmo` (deterministic)

`tests/golden/sheet.bmo` — 1155 bytes, `sha256=cd463c3f66f7d610…`:

```text
1  workbook  calc=auto
2  numfmt    "#,##0.00"
3  sheet     "Summary": A1=42, B2="Revenue"+numfmt, C3=3.14(float),
                       D4=null f="A1*2" deps=[A1], E5=true, F6=#DIV/0!,
                       merges=[[0,0,0,1]]
4  sheet     "Q1": A1=2.5 f="SUM(A2:A10)" deps=[A2,A10]
```

Exercises int/float/text/bool/null/err cells, formula+deps, merges,
duplicate-name and bounds rules (negatives in the suite).

## 5. Conformance

* Bad addresses/out-of-bounds, `v`+`err`/neither, NaN, `f` without
  `deps`, bad deps entries, bad merges, duplicate sheet names, sheet
  with children or non-workbook parent, and drawing images with missing
  worksheet/anchor metadata or an unknown worksheet → `STRUCTURE_INVALID`.
* Compatibility suites (`XLSX↔BMO` value/formula matrices) arrive with
  the importer RFC — no percentage claims until measured.
