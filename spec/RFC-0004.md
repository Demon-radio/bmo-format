# BMO RFC-0004 — Graphics Model (v0.4.0-alpha, DRAFT)

Status: **DRAFT**, depends on RFC-0001 + RFC-0002. Defines canvases,
shapes, images and groups. Raster/vector codecs stay external (stored
as typed assets); this document defines geometry, composition and
referencing.

## 1. Units and numbers

* **bmu**: all geometry integers in thousandths of a millimetre
  (`unit = "mm1000"`, the default and only unit in v0.4). No float
  coordinates — deterministic across renderers.
* Transforms (optional, on any drawing object):
  `{translate?: [int,int], scale?: [number,number], rotateDeg?: number}`.
  Composition order: scale → rotate → translate. Floats appear ONLY here
  (and in opacity); everything else is int.
* Color: `{srgb: bstr(3)}` with optional `a: 0..255`. The text `"none"`
  means unpainted (transparent fill / no stroke).

## 2. Kinds and bodies

### 2.1 `canvas` — `{w: uint>0, h: uint>0, unit?: "mm1000", bg?: color?}`

Children MUST be `shape`/`image`/`group` (plus resource kinds:
`style`, `numfmt`, `list-def` — RFC-0002 resources may live under any
container).

### 2.2 `shape`

```text
{
  shape: "rect"|"ellipse"|"line"|"path" (REQUIRED),
  geom: map (REQUIRED, per type below),
  fill?: color,            # default: opaque black for closed shapes
  line?: { w: uint, color: color }
}
```

Geometry (all ints):
`rect {x,y,w,h}`, `ellipse {cx,cy,rx,ry}`, `line {x1,y1,x2,y2}`,
`path {d: [op,…]}` with ops `["M",x,y]`, `["L",x,y]`,
`["C",x1,y1,x2,y2,x,y]`, `["Z"]`. Wrong op name, arity or non-int
coordinate → `STRUCTURE_INVALID`.

### 2.3 `image`

`{asset: {$asset} (REQUIRED), mime: tstr (REQUIRED), w,h: uint>0,
crop?: map?, sheet?: tstr, anchor?: map?}`

* The `$asset` MUST resolve through `ASSET_TABLE` (R6). BMO never
  invents codecs: `mime` names the bytes (`image/png`, …), renderers
  decode them. `crop` is opaque and preserved.
* Spreadsheet drawings MAY set `sheet` to a unique worksheet name and
  `anchor` to the producer's opaque placement data. They MUST occur under
  the workbook and include both fields together; RFC-0005 defines this
  placement extension.

### 2.4 `group` — `{}`

Transparent container; children follow canvas membership. Exists so
editors can move/select sets as one (and so future transform-inheritance
has an anchor).

## 3. Content-addressing flow (normative example)

```text
image.body.asset = {"$asset": sha256}
        ↓ must be a key of
ASSET_TABLE { sha: { size, mime, chunks: [100] } }
        ↓ chunk 100 (ASSET_DATA, raw bytes)
```

Deduplication falls out naturally: two `image` objects with the same
`$asset` share one slice. Split assets (>2^32−1) list several chunk IDs
in order.

## 4. Chunk mapping, features

* `GENERIC_OBJECT` in v0.x (`0x0030–0x003F` reserved for packed future).
* `DOCUMENT.features` advertises `"graphics.v1"`.

## 6. Conformance

* Bad shape name/geom mismatch, non-int coords, bad path ops, bad
  color, `w/h = 0`, image without asset/mime/size, canvas/slide
  membership violations → `STRUCTURE_INVALID`; dangling `$asset` →
  `DANGLING_REF` (R6).
* Unknown shape types or future geom keys: preserved, never failed
  (ancillary rule) — UNLESS the `shape` discriminator itself is unknown,
  which fails, because a renderer cannot place what it cannot name.
  (Rationale: open failure beats silent mislayout for geometry.)
