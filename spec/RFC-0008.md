# BMO RFC-0008 — Extension Registry & Process (v0.8.0-alpha, DRAFT)

Status: **DRAFT**, depends on RFC-0001 (§13) + RFC-0002 (§5, §9).
Anyone can extend BMO; nobody can break it silently.

## 1. What counts as an extension

New chunk types (`0x0100–0x7FFF`), new object kinds, new `ext` key
namespaces, new `DOCUMENT.features` tokens, new index types, new
compression/encryption/signature suite IDs. Anything else (new files,
new apps) needs no registration at all.

## 2. Hard rules (already normative, collected here)

* Private/experimental range `0x8000–0xFFFF` + kinds prefixed `x-`:
  MUST be ancillary (`CRITICAL = 0`), MUST be preserved byte-exact,
  MUST NOT appear in `requiredExtensions` of a conformant file.
* Registered range: unknown `CRITICAL` chunk → `UNKNOWN_CRITICAL`;
  unknown `requiredExtensions` entry → `UNKNOWN_EXTENSION`; unknown
  `optionalExtensions` → degrade gracefully, never fail.
* Unknown envelope keys, unknown body keys, unknown `ext` content:
  preserved verbatim on round-trip (payloads are never rewritten, only
  re-indexed — preservation is architectural, not aspirational).
* Extension `ext` maps SHOULD namespace keys as `vendor.feature`
  (e.g. `"acme.watermark": {...}`); collisions on unnamespaced keys are
  the extension author's bug, and readers MUST still preserve them.

## 3. Registry (initial contents — amend by RFC only)

| Token / range | Owner | Status |
|---|---|---|
| `model.*`, `text.v1`, `graphics.v1`, `sheet.v1`, `deck.v1` | BMO core | standard |
| `encryption.*` suite names | BMO core (§7) | standard |
| chunk `0x0020–0x00FF` | BMO core (domain packing) | reserved |
| index types `2+` | BMO core | reserved |
| everything `x-` / `0x8000+` | anyone | private, no guarantees |

## 4. RFC process (the bar for `standard`)

```text
Proposal → Discussion → Draft → Review → Experimental → Accepted → Standard
```

* **Experimental** requires: spec text + one implementation + golden
  files + negative tests (the same bar every RFC-0001..0007 cleared).
* **Accepted** requires additionally: a SECOND independent
  implementation passing the same vectors (the stride bug in §8 of
  RFC-0001 and the float-framing bug in the text work were both caught
  exactly this way — the rule exists because it already paid for itself
  three times).
* **Standard** requires: two releases in the wild + interop report
  (A→B→A round-trip matrix with percentages, not adjectives).
