# BMO RFC-0002 — Object Model Framework (v0.2.0-alpha, DRAFT)

Status: **DRAFT 0.2.0-alpha** — experimental, depends on RFC-0001.
Defines the model layer: what objects are, how they nest, how they
reference each other. Text shaping, spreadsheet semantics, and
presentation behavior are RFC-0003+; this document only defines the
framework every domain builds on.

## 1. Principles

1. **Hierarchy as data, not pointers.** Parent links live inside objects;
   child lists are *derived* by query (never stored twice, so they can
   never disagree).
2. **Opaque by default.** A reader that does not understand a `kind`
   MUST preserve its body and MUST NOT fail (RFC-0001 §13). Meaning is
   layered: envelope (this RFC) → kind body (domain RFCs).
3. **References by ID and by hash.** Object-to-object links use stable
   `object_id`s (`$ref`); links to bulk bytes use SHA-256 (`$asset`).
4. **Container reuse.** All model objects in v0.x travel in
   `GENERIC_OBJECT` (0x0010) chunks. Typed binary chunks arrive with
   their domain RFCs (§8).

## 2. Envelope v1

Every `GENERIC_OBJECT` payload is a canonical CBOR map (RFC-0001 §2.5):

| Key | Type | Required | Default | Rule |
|-----|------|----------|---------|------|
| `kind` | text | YES | — | registry key (§5); unknown values MUST be preserved |
| `parent` | uint | YES | — | `object_id` of parent; `0` = root |
| `index` | uint | NO | *derived* | sibling position, 0-based, dense (§4 R4) |
| `role` | text | NO | `""` | named slot within parent (e.g. `"header"`, `"review"`) |
| `rev` | uint | NO | `0` | revision counter; writers SHOULD increment per CoW update |
| `id` | uint | NO | chunk header | if present MUST equal the chunk's `object_id` |
| `body` | any | NO | `null` | kind-specific content (opaque to this RFC unless §6 ref scan) |
| `ext` | map | NO | absent | extension-owned keys; MUST be preserved verbatim |

Backward compatibility: v0.1 files (`hello.bmo`: `{kind,parent,body}`
only) are valid envelope-v1 files — missing `index` means "derive from
`object_id` order", missing `rev`/`role` mean `0`/`""`.

## 3. Identity and lifecycle

* Identity = chunk header `object_id` (RFC-0001 §5.4). The envelope
  never reassigns it (`id` is a cross-check, not a second source).
* Updates use copy-on-write: same `object_id`, new chunk bytes, `rev`
  SHOULD increase by ≥1. Readers MUST accept any `rev` (never reject on
  it); collaboration profiles (later RFC) use it for conflict detection.
* Deletion = directory tombstone (RFC-0001 §7). Children of a tombstoned
  object MUST be tombstoned or reparented in the same commit — a live
  object whose parent is a tombstone fails R2.

## 4. Structural rules (normative, enforced by `validate`)

* **R1 — single root.** Exactly one object has `parent == 0`. Its kind
  SHOULD be `"document"` (domain roots such as `"workbook"` are allowed
  for future document types; validators warn, not fail).
* **R2 — parents exist.** Every `parent != 0` MUST resolve to a live
  (non-tombstone) object in the same directory snapshot.
* **R3 — no cycles.** Every ancestor chain MUST reach `0` within
  `N+1` steps (`N` = live model object count).
* **R4 — sibling order.** Children of one parent are EITHER all-explicit
  (`index` present on every child, values exactly `0..n-1`) OR
  all-implicit (order = ascending `object_id`). Mixing explicit and
  implicit children under one parent is INVALID.
* **R5 — envelope typing.** `kind` text, `parent`/`index`/`rev` uint,
  `role` text, payload a CBOR map. Violations are `CORRUPT`, not
  "unknown".
* **R6 — reference integrity.** `$ref`/`$asset` scan (§6).

Error codes: `STRUCTURE_INVALID` (R1–R5), `DANGLING_REF` (R6),
`CORRUPT` (framing/typing).

## 5. Kind registry

Kinds are short text keys. Bodies of kinds marked *reserved* are opaque
until their RFC lands; validators MUST NOT inspect them beyond §6.

| Kind | Status | Body sketch |
|------|--------|-------------|
| `document` | **defined here** | `{title?: tstr, docType?: tstr}` — root container |
| `section` | **defined here** | `{}` — generic container (children carry meaning) |
| `page` | **defined here (stub)** | `{number: uint}` — geometry arrives in RFC-0004 |
| `note` | **defined here** | `{text: tstr, lang?: tstr}` — plain string holder |
| `annotation` | **defined here** | `{text: tstr, target: {$ref}, author?: tstr}` |
| `paragraph`,`run`,`table`,`row`,`cell`,`list-def`,`style` | defined in RFC-0003 | opaque until then (now: defined) |
| `list` (inline property, not a kind) | defined in RFC-0003 | paragraph list membership |
| `shape`,`image`,`canvas` | reserved → RFC-0004 | opaque map |
| `workbook`,`sheet`,`formula-cell` | reserved → RFC-0005 | opaque map |
| `slide`,`master` | reserved → RFC-0006 | opaque map |

New kinds arrive only via RFC + registry entry. Vendor experimentation
MUST use `x-` prefixed kinds (never unprefixed), MUST be ancillary, and
MUST NOT appear in `requiredExtensions`.

## 6. References (`$ref` / `$asset`)

Inside `body` (and `ext`), maps with these exact keys are links:

* `{"$ref": uint}` — MUST target a live object in the same snapshot
  (any directory ID, usually a model object). Anything else (missing key,
  non-uint value, tombstoned/missing target) is `CORRUPT` / `DANGLING_REF`.
* `{"$asset": bstr(32)}` — MUST be a SHA-256 key present in `ASSET_TABLE`
  (§6 RFC-0001). A `$asset` with no table, or absent from it, is
  `DANGLING_REF`. Value MUST be exactly 32 bytes or the envelope is
  `CORRUPT`.

Scanners walk `body` + `ext` recursively (maps and arrays). A `$ref` key
with a non-uint value, or `$asset` with non-32-byte value, is `CORRUPT`
even if the target would exist — malformed links fail fast.

## 7. KIND_INDEX (secondary `index_type = 1`)

Optional index chunk (`INDEX_SECONDARY`, ancillary) mapping kinds to
sorted ID lists. Lets a reader list "all annotations" without scanning.

Binary payload (LE):

```text
0 u32 version (=1)
4 u32 group_count
8 per group: u16 kind_len, kind_bytes, u32 count, count * u64 object_id (ascending)
```

Groups SHOULD be sorted by kind bytes. Readers MUST verify
`object_id`s resolve (else ignore the index, never fail the open —
indexes are advisory; the directory is authoritative). Writers SHOULD
emit it when a file has ≥2 kinds. `index_type` values `2+` are reserved.

## 8. Chunk mapping and migration

* v0.x writers MUST put every model object in `GENERIC_OBJECT` (0x0010).
* Typed ranges are reserved and MUST NOT be emitted yet:
  `0x0020–0x002F` text/layout, `0x0030–0x003F` graphics,
  `0x0040–0x004F` spreadsheet, `0x0050–0x005F` presentation,
  `0x0060–0x006F` charts/forms/media/annotations, `0x0070–0x00FF` spare.
* When a domain RFC defines a typed chunk, readers MUST support both
  the typed chunk AND the legacy `GENERIC_OBJECT` encoding of the same
  kind, forever (1.x rule). No flag days.

## 9. Versioning

`DOCUMENT.features` advertises model support:
`"model.envelope-v1"`, `"model.kind-index"`. Model extensions go through
`requiredExtensions`/`optionalExtensions` exactly like container
extensions (RFC-0001 §13). Envelope v2 (if ever) MUST keep v1 files
readable — additive optional keys only.

## 10. Test vector: `model.bmo` (deterministic)

`tests/golden/model.bmo` — 1250 bytes,
`sha256(file)=9d7165731d5279d1b2c1fcccf8d83ed611015fb4a96ef1634b61cc9b5023e600`,
`file_id=00..02`:

```text
0     FILE HEADER (64)
64    DOCUMENT (features model.envelope-v1, model.kind-index)
319   OBJECT 1 document  parent=0 index=0 rev=1
427   OBJECT 2 page      parent=1 index=0 rev=1 body={number:1}
522   OBJECT 3 note      parent=2 index=0 rev=1 body={Hello model,en}
634   OBJECT 4 annotation parent=1 index=1 role=review rev=2 target={$ref:3}
772   KIND_INDEX (4 groups, cross-checked against directory)
906   OBJECT_DIRECTORY (4 entries, txn=1)
1094  ROOT_INDEX (M=1 → KIND_INDEX)
1186  FOOTER (64) txn=1 — EOF at 1250
```

`hello.bmo` remains the container vector AND passes envelope validation
under §2 defaults (chain 1→2→3, all-implicit order). Negative vectors
(two roots, cycle, dangling parent/`$ref`, mixed/sparse index) are
asserted in `tests/conformance/test_model.py` and `core/rust/tests/model.rs`.

## 11. Conformance

* **Structure validator**: enforces R1–R6 exactly; `hello.bmo` passes;
  `model.bmo` passes with `kinds == {annotation:[4],document:[1],
  note:[3],page:[2]}` and KIND_INDEX identical to the directory-derived map.
* **Round-trip**: unknown kinds, unknown envelope keys, `ext` content,
  and `role`/`rev` values survive append commits byte-exact (payloads
  are never rewritten, only re-indexed).
* **Advisory indexes**: a corrupt KIND_INDEX MUST NOT fail the open
  (drop it, use the directory); a missing one MUST NOT fail validation.
