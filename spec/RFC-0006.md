# BMO RFC-0006 — Presentation Model (v0.6.0-alpha, DRAFT)

Status: **DRAFT**, depends on RFC-0001 + RFC-0002 (+ RFC-0003/0004 for
content). Defines decks, slides, masters and layouts. Slides compose
existing kinds (paragraphs, shapes, images) plus an opaque media asset.

## 1. Composition over invention

A slide's visible content is ordinary objects parented to it:
`paragraph` (RFC-0003), `shape`/`image` (RFC-0004). This RFC adds only
the scaffolding: order, templates, transitions, notes, and a media
resource for embedded audio/video bytes.

## 2. Kinds and bodies

### 2.1 `deck` — `{}`

Root alternative. Children MUST be `slide`/`master`/`layout` (plus
resource kinds).

### 2.2 `slide`

```text
{
  layout?: { $ref },                       # which layout it was drawn from
  transition?: { type: tstr, durMs?: uint },
  notes?: tstr                             # speaker notes, \n allowed
}
```

* Parent kind MUST be `deck`. Children MUST be `paragraph`/`shape`/
  `image`/`media`/`note`/`annotation`/`table` (plus resources).
* `transition.type` is free text (`"fade"`, `"none"`, …). Unknown types
  MUST be preserved and ignored (a missing animation never fails a
  business file — contrast with geometry, RFC-0004 §6).

### 2.3 `master` / `layout` — maps (theme data opaque in v0.6)

Children of `deck`, distinguished by `role` (`"master"`, `"layout"`).
`slide.layout` SHOULD point at a `layout` object (R6 enforces existence,
not the kind — forward-compatible with future template kinds).

### 2.4 `media`

```text
{
  asset: { $asset: bytes32 },               # REQUIRED, SHA-256 content address
  mime: tstr                                # REQUIRED, "audio/*" or "video/*"
}
```

The referenced asset bytes MUST be preserved unchanged. Media playback,
transcoding, and rendering are out of scope; readers that do not support
the media MIME type MUST retain the asset without interpreting it.

## 3. Chunk mapping, features

* `GENERIC_OBJECT` in v0.x (`0x0050–0x005F` reserved).
* `DOCUMENT.docType = "presentation"`, features `"deck.v1"`
  (plus `"text.v1"`, `"graphics.v1"` when composed).

## 4. Test vector: `deck.bmo` (deterministic)

`tests/golden/deck.bmo` — 1650 bytes, `sha256=db6c538fc2b6271d…`:

```text
1  deck
2  master   role=master
3  layout   role=layout "Title + Content"
4  slide    layout=$ref(3), transition fade/300ms, 2-line notes
5  paragraph  (child of slide 4, align=center)
6  run        "Hello BMO"
7  slide    transition none
8  shape    blue line (child of slide 7)
```

Proves cross-domain composition through one validator.

## 5. Conformance

* Slide with non-deck parent, illegal slide children, malformed
  transition/notes, deck with illegal children → `STRUCTURE_INVALID`;
  dangling `layout` ref → `DANGLING_REF`.
* Animation *playback* is renderer scope; the format guarantees the
  declaration round-trips.
